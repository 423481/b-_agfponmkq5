# مُهر — سامانه‌ی خودکنترلی خط تولید (سورس)

این پوشه‌ی **سورس** برنامه است. برنامه‌ی نهایی یک فایل است (`dist/index.html`) که با یک دستور از همین فایل‌ها ساخته می‌شود.
رفتار برنامه با نسخه‌ی تک‌فایلی قبلی (v167.18) یکسان است؛ فقط کد مرتب و فصل‌بندی شده است.

## چطور بسازم؟

```
node build.js
```

خروجی: `dist/index.html` — همین فایل را در گیت‌هاب جایگزین کنید.
ساخت قبل از تولید خروجی بررسی می‌کند که هر فایل بدون خطای نوشتاری باشد و هیچ تابعی دو بار تعریف نشده باشد.
فقط Node لازم است؛ بسته‌ی اضافه نیاز نیست.

## ساختار پوشه

```
src/
  index.template.html     اسکلت صفحه
  manifest.json           ترتیب فایل‌ها (ترتیب مهم است)
  assets/                 عکس‌ها (ورود، آیکن)
  css/                    ظاهر برنامه (۹ فایل، به ترتیب)
  js/                     کد برنامه، فصل‌به‌فصل (پایین را ببینید)
    data/                 فهرست آیتم‌های بازرسی هر ایستگاه
build.js                  ساخت خروجی
```

## راهنمای تغییرهای رایج

**متن یک آیتم بازرسی را عوض کنم**
`src/js/data/` ← فایل همان ایستگاه (مثلاً `11-trim.js`) ← در `SHEETS.<ایستگاه>` متن را در `items` پیدا و ویرایش کنید.
متن‌های مخصوص اکستند در همان فایل زیر `EXTEND_ITEMS` (متن‌ها) و `EXTEND_GROUPS` (گروه‌ها) هستند.
⚠ اگر آیتمی را عوض یا جابه‌جا می‌کنید، رکوردهای قبلاً ثبت‌شده ممکن است به آیتم دیگری اشاره کنند؛ اول روی داده‌ی آزمایشی امتحان کنید.

**ایرادهای رایج، دلیل توقف، کسری‌ها، کد تحویل با کسری** ← نیازی به کد نیست: از خود برنامه، «⚙ مدیریت ← فهرست‌ها».

**طول مجاز شماره‌ها** ← از «⚙ مدیریت ← تنظیمات». مقدار پیش‌فرض: `LEN_DEF` در `js/05-sheets-data.js`.

**نام و عنوان ایستگاه‌ها** ← `js/05-sheets-data.js` (`STATION_NAME`، `STATION_TITLE`).

**رنگ‌ها** ← `css/01-theme-base.css`، بلوک `:root` (حالت روشن) و بلوک‌های حالت تاریک زیر آن.

**دسترسی نقش‌ها** ← `js/63-management-roles.js` (`ROLE_PERMS`).

**شماره‌ی نسخه** ← `js/00-settings.js` (`APP_VER`). با هر تحویل عوض کنید تا روی گوشی معلوم باشد کدام نسخه باز است.

**ظاهر PDF و Excel** ← `js/51-reports.js`.

**یک ایستگاه جدید اضافه کنم** ← کار برنامه‌نویسی است. نام فنی ایستگاه مشابه (مثلاً `roll`) را در همه‌ی فایل‌ها جست‌وجو کنید تا ببینید کجاها لازم است.

## نام‌گذاری

- **کلیک‌ها:** هر تابع `click…` یک «توزیع‌کننده» است. اقدام‌های بزرگ آن در تابع جدا به شکل `نام‌توزیع‌کننده_اقدام` نوشته شده‌اند (مثلاً `itemMark_savenote` یعنی اقدام `savenote` از `clickItemMark`). برای پیدا کردن کار یک دکمه، مقدار `data-act` آن را در فایل‌ها جست‌وجو کنید.

## قاعده‌ها (بخوانید)

1. **ترتیب فایل‌ها در `manifest.json` را عوض نکنید.** کدهای CSS و بخش‌های راه‌اندازی به ترتیب اجرا می‌شوند. `99-boot.js` باید آخر باشد.
2. **یک تابع فقط در یک فایل تعریف شود.** `build.js` تکراری‌ها را گزارش می‌دهد.
3. **کد حساس:** قفل حذف خودروهای بایگانی‌شده (`assertNotArchived`)، بررسی شماره‌ی تکراری (`conflictFor`)، دسترسی بستن ایراد (`canCloseItem`) و پاک‌کردن داده (`wipeAll`) را بدون هماهنگی تغییر ندهید.
4. بعد از هر تغییر `node build.js` را بزنید و برنامه را با `?demo=1` (حالت آزمایشی، بدون سرور) در مرورگر باز کنید.
5. برای یکنواخت ماندن شکل کد: `prettier --write src` (تنظیمات در `.prettierrc.json`).
6. در حالت آزمایشی داده‌ها فقط در مرورگر می‌مانند؛ به سرور واقعی دست نمی‌زند.
